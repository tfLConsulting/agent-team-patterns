# Design considerations

These are initial design proposals informed by practice, not comparative research results. Each application must establish its own fit. Start with the failure you need to prevent, choose a mechanism, and observe whether it helps.

| Consideration | Read | Question to settle locally |
|---|---|---|
| Planning, tasks, workstreams, disposition | [Operating cycle](operating-cycle.md) | What outcome makes the work worth doing? |
| Human attention and decision rights | [Attention](attention.md) | What really needs this person's judgment? |
| Consequences and feedback | [Consequences](consequences.md) | What should change in our beliefs or direction? |
| Exposure, tests, controls, residuals | [Risk and evidence](risk-and-evidence.md) | What could still go wrong after the checks? |
| Sources, context, records, retrieval | [Information strategy](information-strategy.md) | Can the next session find and verify what matters? |
| Capture, refinement, uncertainty, re-entry | [Planning and replanning](planning-and-replanning.md) | Is this still the right plan, and what would reopen it? |
| Control calibration, context quality, resource choice | [Evaluating the system](evaluating-the-system.md) | Do our checks and instructions actually help? |
| Delegation, ownership, policy change, enforcement | [Authority and policy](authority-and-policy.md) | Who can decide, act, and change the rules? |
| Capacity, interruptions, learning | [Execution and recovery](execution-and-recovery.md) | Can we stop, resume, and learn without losing intent? |

Cross-cutting choices include authority, reversibility, privacy, evidence freshness, dependencies, ownership, fairness, cost, review independence, and the difference between delivery and observed benefit. These are design axes, not fields every task must fill. Read the [policy-choice register](../applications/policy-choices.md) before treating an example rule as a principle.
