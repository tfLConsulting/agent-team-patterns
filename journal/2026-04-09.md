# Session 7 — Guide/Pattern Redundancy

**Date:** 2026-04-09
**Focus:** Editorial roadmap item #3 — reduce redundancy between the agent-team-guide and individual pattern files.

## Context

The methodology review (session 2) flagged that the guide restates content from pattern files rather than referencing them. Sessions 4 and 5 tackled the inverse — retiring standalone files whose content was mostly redundant with the guide. Now we face the remaining case: the guide itself contains passages that duplicate what the pattern files say.

The key design question: should the guide be a self-contained document that summarizes patterns (at the cost of duplication), or a routing document that references pattern files (at the cost of requiring readers to jump between files)? Or some hybrid?

## Work

### Analysis phase

Dispatched an agent to map every overlap between the guide and the 5 pattern files that have corresponding guide sections. The analysis classified each overlap (full restatement, summary, different angle) and evaluated three structural options:

- **Option A (guide as routing document):** Too aggressive — the guide's strength is its integrated narrative, and gutting Section 2 would undermine the document's primary value.
- **Option B (guide as self-contained, pattern files as stubs):** Wrong direction — the guide is already ~600 lines and pattern files need to be independently referenceable from other projects.
- **Option C (hybrid):** Best fit — guide keeps contextual framing (problem/solution, how patterns relate), defers to pattern files for depth.

Overlap severity:
| Pattern file | Guide section | Severity |
|---|---|---|
| self-modifying-briefs.md | Section 9 | Very High (~80% verbatim) |
| three-tier-memory.md | Sections 2.3, 3.1 | High |
| role-design.md | Section 2.1 | Medium |
| brief-anatomy.md | Section 2.2 | Medium |
| file-based-coordination.md | Section 2.4 | Medium |
| writing-for-ai.md | (none) | None |
| learning-from-practice.md | (none) | None |

### Editing phase

Chose Option C and dispatched editing work. Changes to `agent-team-guide.md`:

- **Section 2.1-2.4:** Each now has a tight problem/solution framing with a link to the pattern file for depth. Removed duplicated lists and mechanism descriptions.
- **Section 9:** Major surgery. Reduced from a large restated block to framing paragraph + single-sentence scope/constraints summary + the guide-unique "Premature Rigidity" subsection + link.
- **All other sections untouched.**
- **Pattern files unchanged.**

Net result: 12 insertions, 61 deletions. Guide went from ~604 to 555 lines. Zero content lost — everything removed exists in better-developed form in the pattern files.

## Practice Observation

The analysis/execution split worked well here. The analysis agent needed to read 6 files and do careful comparison — exactly the kind of context-heavy work that would have overwhelmed the team lead's window. Having the overlap map as a structured deliverable made the editing dispatch straightforward. The Option A/B/C framework was also useful — it forced consideration of alternatives rather than jumping to the first plausible approach.
