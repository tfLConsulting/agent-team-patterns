## Practice Observation

Three-tier-memory was the most self-referential elevation — the pattern describes the memory system that the team uses to manage the pattern library, including the memory files that were read to gather evidence for elevating this very pattern. The team-lead's memory.md is simultaneously a worked example cited in the pattern and the operational state file that determined this session's focus. This self-referentiality didn't cause problems, but it's worth noting: when a methodology describes its own tools, the evidence for "does this work?" is inseparable from "we're currently using it." The confidence is real but circular.

The elevation phase as a whole (sessions 16-20) produced a consistent process: read the current file, gather evidence from learning-from-practice.md and repo history, rewrite with inline qualifiers, add anti-patterns and worked examples, expand cross-references. Five patterns, five sessions, same structure. The team-coach flagged this as approaching codifiable (R4.3) — worth watching whether elevation becomes a standing practice or was a one-time roadmap.
