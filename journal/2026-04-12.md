# Session 8 — Mining a Live Project for Patterns

**Date:** 2026-04-12
**Mode:** Directed
**Focus:** Extract patterns from a live agent team project. The operator's core thesis: disciplines have processes, and encoding them as structured skills elevates AI from random intuition to repeatable quality.

## Context

The operator has been running agent teams on a real product for 150+ sessions and brought a wealth of observed patterns to extract. The primary thesis — that established discipline methodologies (UX, content, SEO, analytics, testing) should be encoded as structured skills rather than left to agent improvisation — is supported by a library of 22 skills across 7 domains in the live project.

The operator also flagged several other veins: memory architecture refinements, hypothesis expansion (investigation threads that evolve rather than complete), load-bearing beliefs with kill conditions, measurement skepticism, session transaction protocols, and bounded mission teams. One session can't mine all of these — narrow focus applies.

## Research Phase

Dispatched three parallel research agents to explore the live project from different angles:

1. **Agent architecture** — found patterns for team coach meta-layer, specialist-over-generalist economics, session transaction protocol with dirty-close detection, file-based information flow (output files, not shared context), living investigation threads, cross-product team isolation, and bounded mission teams with sunset conditions.

2. **Skills and processes** — the core finding. 22 skills encode discipline processes using a three-tier progressive disclosure structure (metadata → instructions → references). Key mechanisms: anti-patterns as first-class citizens, human checkpoints at phase boundaries, quality rubrics with dimensional scoring, staged execution across fresh contexts to reduce anchoring, and a meta-skill for building skills. The system is self-reinforcing.

3. **Memory and project approach** — journal as a team-level structure (not just agent-level), projects manifest with lifecycle states, scratchpad intentionally disposable, hypothesis expansion via living investigation threads, load-bearing beliefs with kill conditions, measurement skepticism as a core principle ("the measurement is wrong more often than the product is broken").

## Post-Session Addition: Closing the Self-Consistency Loop

The operator spotted a structural gap: the team-coach evaluates composition but has no instruction to check whether the team practices its own methodology. We could document discipline processes and never use them; the coach wouldn't notice.

Fixed with two changes to the coach brief:
- **New step 5:** Read the methodology files as part of every review
- **New criterion — "Methodology self-consistency":** Explicitly checks whether the team's operations reflect its published patterns. Asks for specific gaps, not vague observations.

This is a self-modification worth noting. It means every future pattern we write becomes something the coach will evaluate us against. That's the forcing function that prevents the methodology from becoming aspirational documentation that the team itself ignores.

## Late Addition: Coaching Framework Research

The operator was simultaneously working on a meta-framework for coaching in the live project (session 173). Researched this and found a substantial upgrade to how coaching works:

- **Five-dimension assessment** replacing composition-only reviews (specification quality, state management, process maturity, information architecture, evolutionary fitness)
- **Maturity ladder** (0=ad hoc → 4=refined) per dimension
- **Backward validation** of all recommendations with outcome tracking
- **Framework self-reflection** — the coach evaluates its own framework
- **Codification ladder** — when and how to formalize patterns (brief → playbook → protocol → skill)

Full working material saved to `agents/team-lead/scratchpad.md` for next session.
