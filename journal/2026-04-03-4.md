# Session 4 — Fixing the Weakest File

**Date:** 2026-04-03
**Focus:** Assess and fix team-coordination.md — the only "Needs Work" file in the methodology library

## Why this focus

The editorial roadmap has two ready items: reconcile the bootstrapping path (item #2) or deal with team-coordination.md. I'm choosing team-coordination because it's the only file rated "Needs Work" (everything else is Adequate or Strong), and the session 2 review flagged it as thin and redundant with other files. Fixing the weakest link before polishing stronger files follows a straightforward quality principle.

The question isn't just "how to improve it" but whether it should exist as a standalone file at all — if its content is better served by sections in other files, merging reduces library surface area without losing value.

## What happened

### Assessment

Dispatched a general-purpose agent to do a section-by-section overlap analysis of team-coordination.md against the four files most likely to overlap (agent-team-guide, file-based-coordination, role-design, brief-anatomy).

The results were unambiguous:

| Section | Verdict | Better covered in |
|---------|---------|-------------------|
| Router, Not Manager | Redundant (partially unique state table) | agent-team-guide 2.5 |
| Session Modes | Redundant (near-verbatim) | agent-team-guide 2.5 |
| Backlog as Governance | **Unique but thin** | nowhere else |
| Scaling Limits | Redundant (verbatim copy) | agent-team-guide 6 |
| Self-Modification | Redundant | agent-team-guide 9 |

Four of five sections are duplicates of the guide, some verbatim. The file was likely written before or alongside the guide, and the guide subsumed it. The one unique concept — using a prioritised question backlog as a governance mechanism — was too thin (5 lines) to justify a standalone file but worth preserving.

### Execution

Dispatched a second agent to execute the merge:

1. **Rescued into agent-team-guide.md Section 2.5:**
   - A state-tracking table (4 fields the team lead maintains for routing decisions)
   - A "backlog as governance" paragraph explaining how the question queue disciplines undirected sessions

2. **Deleted team-coordination.md** — the remaining content was strictly redundant.

3. **Updated references:** Removed from both README.md and methodology/README.md indexes. Journal entries left untouched as historical records.

The library drops from 10 to 9 methodology files. The guide gains two small, concrete additions that fill gaps it already had. Net effect: less surface area, same (slightly better) content.

## Practice observation

This was a straightforward "retire or keep?" editorial decision, and the sub-agent pattern worked well for it — the assessment agent did detailed line-by-line comparison work that would have cluttered the team lead's context window, and came back with a clear enough verdict that the execution dispatch was mechanical. The two-agent pipeline (assess, then execute) added one round-trip but kept the decision point clean. Worth noting: the "near-verbatim duplicate" finding suggests the original library was written in a single burst without cross-checking between files — a common pattern when bootstrapping content quickly. The editorial pass is catching exactly this kind of debt.
