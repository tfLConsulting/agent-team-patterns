# Session 22 — Scouting an external team for pattern-library gaps

**Date:** 2026-04-24
**Mode:** Directed
**Focus:** The operator pointed at an external agent team running on a different project and asked us to harvest ideas for improvements. Strict constraint: no identifying information about that project — no paths, no product/client/people names, no domain references — may enter this repo. We describe ideas abstractly.

## Session plan

1. Dispatch a general-purpose sub-agent to scout the external team directory. It reads; we don't.
2. The sub-agent compares what it finds against our current methodology (16 patterns) and team structure (team-lead + team-coach, candidate specialists researcher + curator).
3. It returns only abstracted, anonymized ideas — ranked by fit — with strict redaction rules baked into the brief.
4. We synthesize findings here, decide what (if anything) to act on this session, and queue the rest.

Starting the scout now.

## What the scout found

The sub-agent returned a clean, abstracted report in three sections. A warning fired about scope escalation (the agent read outside the working directory) — that was intentional and directed by the brief; no identifying info made it into the report. Summary of findings, fully abstracted:

**New ideas worth consideration (8 total).** Strongest three:

1. **Live-heading artefact + narrow keeper agent** — splits strategy-holding in two: a long-form strategy doc, plus a one-screen "current bets" file owned by a dedicated narrow agent whose sole job is diffing that file on evidence-shift triggers. Each bet carries an explicit kill condition with numeric triggers. Distinct from `load-bearing-beliefs.md` (which describes the principle) — this is the concrete artefact + role split.
2. **Dual-gate retro items** — forcing functions with two expiry conditions (session count AND data-readiness), triggered on whichever is later. Prevents verdicts on stale data just because a session counter ticked.
3. **Ruler-change tagging + briefing-provenance checks** — small protocols extending measurement discipline: tag definition-shifts explicitly (distinct from corrections/reframes), and re-measure remembered numbers before acting on them.

Other new ideas noted for later: scheduled bet-challenge cadence with KEPT/REFRAMED/REPLACED verdicts; predictions register as a distinct artefact class from investigation threads; projects directory as a typed lifecycle manifest; hibernation as a first-class agent state with a disciplined trigger.

**Refinements to existing patterns (5).** Team-coach recommendation tracker with outcome lifecycle and backward-validation at next review; framework versioning with explicit cap rules; memory-experiments file as an artefact shape alongside memory; journal entries with an explicit "alternatives considered" section; sharper framing for undirected sessions ("build conviction about what to build next," not dashboard rotation).

**Anti-patterns / calibration (3).** Edit-log entries accrete to essay-length even under "one-screen" discipline. Scheduled cadences risk ritualised theatre. Over-specified protocols accumulate past a threshold where meta-process becomes its own coordination burden — strong negative evidence for the "idle agents are free" claim.

## Decision

Narrow session focus: act on the smallest, highest-evidence addition this session — ruler-change tagging + briefing-provenance checks — because both directly extend an existing pattern (`measurement-skepticism.md`), are tightly scoped, and carry clean evidence of having caught real failures in the source team. Queue everything else as candidates for future sessions.

**Explicitly NOT acting on in this session:**
- Live-heading + keeper agent (bigger structural change; deserves its own design session; our team hasn't felt the pain it solves)
- New pattern file for process-inventory-as-cost (tempting, but the codification-ladder pattern already argues the core point; wait for genuine pain)
- New candidate specialists (scout's findings don't override our two-part test)

The anti-pattern finding — that over-specified protocols accrete — is load-bearing for this decision. Adding seven ideas because they're interesting is exactly the failure mode called out.

## Practice observation

The research-before-action principle worked cleanly here — dispatching a general-purpose scout kept the main context clean and produced a report that was usable directly. The anonymization contract baked into the scout's brief worked: grepping the outputs for obvious identifying strings came back empty on the first pass. The directed-mode protocol (journal-first, single focus, dispatch agents, synthesize, decide) is now feeling well-worn rather than effortful — that itself is a useful signal that the protocol has stabilised.

One thing I'd flag: the scout returned ~16 discrete ideas. The discipline here was *not* acting on all of them. The bias toward action in the team-lead role (called out in my own brief) would have happily converted eight of them into new pattern files. Deferring is a real practice, not just inaction.
