# Session 2 — Methodology Review

**Date:** 2026-04-03
**Focus:** Review the methodology files for quality, gaps, and practitioner usefulness

## Why this focus

The patterns library has 10 methodology files carried over from internal use. Before doing anything else — before promotion, before new patterns, before refinement — we need to know what we actually have. What's clear and useful? What's rough? What's missing? This is the foundation for everything that follows.

## What happened

Dispatched a general-purpose agent to review all 10 methodology files + README against clarity, evidence quality, actionability, and practitioner usefulness. The review was thorough — every file assessed individually, cross-cutting patterns identified, gaps catalogued.

### Three structural issues

1. **Safety gap in three-tier-memory.md.** Presents the pattern cleanly without mentioning its most documented failure mode — the Buttondown incident where pruning lost load-bearing decisions. A practitioner reading only this file would implement the pattern blind to a known danger.

2. **Split bootstrapping path.** README routes readers to bootstrapping-protocol.md for getting started, but the actual steps are in agent-team-guide.md Section 4. The two files have unreconciled overlaps (experiment log setup only in bootstrapping, step-by-step only in guide).

3. **Guide/pattern redundancy.** Role design, self-modification, and brief anatomy each appear three times across the library (in their pattern file, in the guide, and in another pattern file). The guide was written first as a monolith; pattern files were extracted but the guide wasn't trimmed.

### Gaps identified

Missing patterns: error recovery, human-agent interface, strategic backlog (referenced but never documented), cost/resource management. Also noted: the library is implicitly Claude Code-specific without acknowledging this for practitioners on other platforms.

### Editorial roadmap (decided)

1. Fix three-tier-memory.md — add known risks section, cross-references
2. Reconcile bootstrapping path — either move steps or add explicit cross-reference
3. Reduce guide/pattern redundancy — guide becomes synthesizer, not restater
4. Add concrete example — reference existing agents/ as a living worked example
5. Add full citations to writing-for-ai.md

### What didn't come up

No team composition issues flagged. The review agent worked well for this task — reading 10 files and producing a structured assessment is exactly what a general-purpose sub-agent excels at. No need for a specialist "curator" agent yet; this task didn't recur enough to warrant one.

## Practice observation

This was the team lead model working as designed: dispatch the analytical work, synthesize the result, make decisions. The review agent had the full context of all 10 files simultaneously, which produced cross-cutting observations (redundancy, inconsistencies) that wouldn't emerge from reviewing files one at a time. Journal-first protocol meant the session focus and rationale were captured before any work started — useful if I'd needed to change direction mid-session.

This is the smallest-scope, highest-impact improvement — addressing a real safety gap in ~10 lines. After that, consider whether team-coordination.md (the only "Needs Work" file) should be merged into team-coordination patterns elsewhere or rewritten.
